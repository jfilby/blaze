# Blaze Pulse

A real-time HTTP benchmark dashboard: a Blaze program that serves a dashboard,
measures every request it handles, and publishes what it measured over a
Server-Sent Events stream.

- `main.ts` — the program: the server, the measurements, the event stream.
- `web/` — the dashboard: HTML, CSS and vanilla JavaScript, with the charts
  drawn as SVG.
- `bench/load.sh` — the load: a separate process that drives `oha` or `wrk`
  against the server and reports what it measured.

The design and the decisions behind it are written down in
[`docs/specs/blaze_pulse.md`](../../docs/specs/blaze_pulse.md).

## Building

The program is built by Blaze, with the facil.io HTTP runtime beside it:

```sh
cd src/compiler
node cli.ts build ../../src/programs/pulse/blaze.toml
```

The binary is written beside the project's sources as `pulse`.

A build without a model (the deterministic half of the build, which needs no
credential) writes the same program:

```sh
cd src/compiler
node offline-build.ts ../programs/pulse /tmp/pulse-work
```

## Running

The program reads its own files from `web/`, so it is started from the
directory that holds it:

```sh
cd src/programs/pulse
../../src/programs/pulse/pulse 8080
```

The port is the first argument, and it is 8080 when no argument is given. The
message the program writes is printed when it starts; the dashboard answers a
moment later.

Open <http://127.0.0.1:8080/> in a browser.

## Loading

The load is generated by a separate process, and the program never generates
any itself: a benchmark that the server under test also generates is not a
measurement of anything.

```sh
bench/load.sh 8080 10s 50
```

The arguments are the port, the length of the run (`10s`, `2m`, or a number of
seconds) and the number of connections. The script drives `oha` (asked for
first) or `wrk`, opens the measurement window on the server, posts what was
measured back to it, and closes the window.

The dashboard shows the server's own measurements (the requests it served, the
latency of each of them) and the report of the load generator (its rate, its
percentiles, its errors).

Neither `oha` nor `wrk` is installed by this project. Install one of them:

- <https://github.com/hatoo/oha>
- <https://github.com/wg/wrk>

## The routes

| Route | What it does |
|---|---|
| `GET /` | the dashboard |
| `GET /app.js`, `GET /style.css` | the dashboard's own files |
| `GET /events` | the event stream: a snapshot every time the server has one |
| `GET /api/state` | one snapshot, as JSON |
| `GET /api/heartbeat` | the dashboard's own heartbeat; it is not counted as load |
| `POST /api/bench/start` | opens the measurement window |
| `POST /api/bench/stop` | closes it |
| `POST /api/bench/result` | records the report of the load generator |
| `GET /ping` | the route the load generator drives |

## What is measured

- **The server's own numbers**: the requests it served, the ones it could not
  answer, the bytes it wrote, and the latency of every request it handled (the
  percentiles are read out of the last 256 requests, in microseconds).
- **The rate**: computed by the dashboard, because a rate is a question about
  two readings of the counter and the time between them, and the time between
  them is the browser's to know.
- **The load generator's report**: the rate, the percentiles and the error
  count it measured, as it posted them.

The numbers are the server's own: nothing is estimated and nothing is carried
over from a previous run. The window the load generator measures in is opened
before the run and closed after it, so the numbers of a run are the numbers of
that run.
